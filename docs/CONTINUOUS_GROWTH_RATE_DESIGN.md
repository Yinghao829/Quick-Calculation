# 连续随机增长率生成方案

> 状态：设计阶段  
> 目标：替换当前固定增长率池，生成数值不规则、概率分布自然、且不超出题材现实边界的增长率。

## 1. 结论

可以实现。

但“完全随机”不能理解为所有题材都从同一个无限范围内均匀抽取。更合理的定义是：

> 在每个题材允许的现实范围内，连续随机生成增长率；小幅变化出现概率高，大幅变化出现概率低，极端变化只在允许的题材中低概率出现。

因此，方案采用三层约束：

```text
题材现实边界
    ↓
正负方向与波动区间
    ↓
连续随机采样 + 小值高概率分布
    ↓
关系校验与题目生成
```

这样可以同时满足：

- 不再依赖 `0.05`、`0.10`、`0.125` 等固定候选值。
- 允许出现 `7.43%`、`-3.18%`、`21.67%` 等不规则增长率。
- 小幅增长或下降更常见。
- 大幅增长、负增长和极端增长不会脱离题材实际。
- 可以为低基数、高波动题材开放 `50%` 甚至更高的增长率。

## 2. 当前实现

当前实现位于：

- `app/src/main/java/com/example/quickcalculation/domain/generator/GrowthRatePool.kt`
- `app/src/main/java/com/example/quickcalculation/domain/generator/GenerationUtil.kt`

当前流程是：

1. 根据难度从 `GrowthRatePool` 的固定列表中按权重抽取。
2. 判断增长率是否位于当前题材的 `growthRange` 内。
3. 最多重试 40 次。
4. 如果没有抽到符合范围的值，则使用 `0.5%` 固定步长随机兜底。

当前方案的问题：

- 候选增长率有限，重复率会比较高。
- 生成结果容易集中在常见整数或常见分数。
- 列表权重需要人工维护，新增题材时还要同步调整。
- 无法自然表达“范围内任意不规则数值”。
- `0.5%` 步长兜底仍然是离散随机，不是真正的连续采样。

## 3. 数值表示约定

程序内部继续使用小数表示增长率：

| 展示值 | 内部值 |
|---|---:|
| `10%` | `0.10` |
| `7.43%` | `0.0743` |
| `-3.18%` | `-0.0318` |
| `125%` | `1.25` |

设计上应区分两个概念：

1. **采样精度**：生成器内部保留的随机精度，避免过早舍入导致分布失真。
2. **展示精度**：题干、选项、答案和解析中展示的精度，由难度策略控制。

严格意义上的连续随机数几乎不可能在界面中完整展示。因此，实际实现应采用：

```text
内部连续采样
    ↓
按难度进行可控量化
    ↓
使用统一精度生成题干、答案和解析
```

量化不是回到固定增长率池，而是将连续随机结果限制到合理的小数位。例如困难模式可以展示到百分比小数点后两位，但候选值仍然来自连续随机过程，而不是预先列举。

## 4. 题材现实边界

增长率的硬边界必须由题材决定，不能使用一个对所有题型通用的 `-50%..50%` 范围。

当前 `TopicRepository` 中的实际范围如下：

| 题材 | 当前范围 | 说明 |
|---|---:|---|
| 国内生产总值 | `2%..12%` | 通常为正增长 |
| 社会消费品零售总额 | `3%..15%` | 正增长为主 |
| 进出口总额 | `-15%..20%` | 允许较明显的正负波动 |
| 规模以上工业增加值 | `2%..12%` | 当前配置为正增长 |
| 固定资产投资 | `-10%..15%` | 允许负增长 |
| 居民人均可支配收入 | `2%..10%` | 通常为稳定正增长 |
| 常住人口 | `0%..2%` | 低增长或接近不变 |
| 居民消费价格 | `0%..4%` | 当前配置为低幅变化 |

这些范围应视为**硬约束**：

```text
rate >= growthRange.start
rate <= growthRange.endInclusive
```

用户提出的以下范围可以支持：

- `-10%..10%`
- `-10%..-50%`
- `10%..50%`
- `50%` 以上甚至更大

但只能配置给现实上允许高波动的题材，例如低基数业务、初创业务、新增产品、极端年份的进出口或销量数据。GDP、人口、居民收入等题材不应因为算法支持大范围，就自动允许 `50%` 以上增长。

此外，任何增长率都必须满足：

```text
1 + rate > 0
```

也就是增长率不能达到或低于 `-100%`，否则反推现期量时会得到零或负数。

## 5. 增长率分布

### 5.1 采用连续随机，而不是固定候选池

不再使用：

```kotlin
listOf(0.05, 0.10, 0.125, ...)
```

而是在题材的合法区间内生成连续随机值：

```text
rate = sampleContinuousRate(topicProfile, difficulty, random)
```

每次采样都可以得到新的不规则数值，但仍然受到题材范围、正负方向和难度限制。

### 5.2 按绝对值分段

为了实现“小数据概率高，大数据概率低”，将增长率按绝对值划分为几个波动区间。以下区间使用百分比表示：

| 波动区间 | 示例 | 默认定位 |
|---|---|---|
| 小幅变化 | `0%..10%` | 主要样本 |
| 中幅变化 | `10%..50%` | 少量样本 |
| 大幅变化 | `50%..100%` | 低概率尾部 |
| 超大变化 | `100%` 以上 | 仅特殊题材允许 |

区间不是全局固定开放，而是与题材硬边界求交集：

```text
可采样区间 = 题材硬边界 ∩ 波动区间
```

例如：

- GDP 的硬边界是 `2%..12%`，只能采样到小幅区间和少量中幅区间前段。
- 进出口总额的硬边界是 `-15%..20%`，可以出现正负增长，但不会达到 `50%`。
- 某个低基数新业务的硬边界是 `-50%..150%`，才允许低概率生成 `50%` 以上增长。

### 5.3 区间权重

困难模式可以采用如下初始权重，后续通过统计测试调整：

| 区间 | 初始权重 |
|---|---:|
| 小幅变化 | `70%` |
| 中幅变化 | `24%` |
| 大幅变化 | `5%` |
| 超大变化 | `1%` |

如果题材的硬边界没有覆盖某个区间，该区间自动移除，权重重新归一化。

难度不应简单地改变题材范围，而应主要影响分布：

| 难度 | 小幅变化 | 中/大幅尾部 | 展示精度 |
|---|---:|---:|---|
| 简单 | 更高 | 更低 | 较粗 |
| 中等 | 默认 | 默认 | 中等 |
| 困难 | 适当降低 | 适当提高 | 更细 |

困难模式仍然保持小幅增长率占多数，只是增加不规则值、中幅变化、负增长和尾部样本的出现机会。

### 5.4 区间内的非均匀采样

仅仅在区间内均匀随机还不够，因为 `0%..50%` 中每个值出现概率相同，会导致大值过多。

可以使用幂函数对区间内的数值进行偏置：

```text
u = random.nextDouble(0.0, 1.0)
x = lower + (upper - lower) × u^k
```

其中：

- `u` 是 `[0, 1)` 的均匀随机数。
- `k > 1` 时，结果更靠近 `lower`，小值概率更高。
- `k = 1` 时，结果为普通均匀分布。
- `k` 越大，小值聚集越明显。

对于负增长率，先生成绝对值再添加负号：

```text
rate = -magnitude
```

对于正增长率：

```text
rate = magnitude
```

这样可以生成不规则数值，同时保持“小幅变化更常见”的特征。

## 6. 正负方向

正负增长不能简单使用 `50%` 对 `50%` 的概率。方向应由题材配置决定：

| 题材特征 | 正负方向策略 |
|---|---|
| GDP、收入、人口 | 只生成正增长或零增长 |
| 进出口、固定资产投资 | 正负增长都允许 |
| CPI、工业增加值 | 根据题材范围决定，通常正增长或小幅波动 |
| 高波动低基数业务 | 正负增长都允许，尾部概率更高 |

对于同时允许正负增长的题材，可以配置：

```text
positiveProbability
negativeProbability
zeroProbability
```

但这些概率只能在题材硬边界允许时生效。比如题材范围为 `0%..4%` 时，负增长概率必须自动变为零。

## 7. 题材配置建议

当前的 `growthRange` 可以继续作为最低兼容配置。后续如果需要表达更细的现实特征，建议将增长率配置抽象为独立的分布配置，例如：

```text
GrowthRateProfile
├── hardRange              // 绝对硬边界
├── typicalRange           // 常见范围
├── positiveProbability    // 正增长概率
├── negativeProbability    // 负增长概率
├── zeroProbability        // 零增长概率
├── tailWeight             // 尾部权重
└── bias                   // 区间内向小值偏置程度
```

其中：

- `hardRange` 保证不脱离现实。
- `typicalRange` 定义大多数样本出现的位置。
- `tailWeight` 控制罕见的大幅变化。
- `bias` 控制小值与大值的相对概率。

建议优先保留当前题材范围，先验证随机分布，再逐步为特殊题材扩展范围，不要一次性放开所有题材的 `50%` 以上增长率。

## 8. 与数据生成的关系

增长率生成后，其他数据必须根据公式反推，不能独立随机：

### 已知基期量和增长率

```text
B = sampleBase(...)
r = sampleRate(...)
A = B × (1 + r)
X = A - B
```

其中：

- `B` 是基期量。
- `A` 是现期量。
- `X` 是增长量。
- `r` 是内部小数形式的增长率。

必须校验：

```text
B > 0
A > 0
X = A - B
r = X / B
```

如果负增长率导致现期量不满足正数约束，应该重新采样，而不是强行修正结果。

### 基础量大小的概率

如果“数据大小概率”也需要遵循小值高、大值低，`sampleBase` 目前的均匀分布可以同步改造：

```text
base = lower + (upper - lower) × u^p
```

对于跨度很大的数据，也可以使用对数尺度采样，避免 `80000..150000` 或 `1000..50000` 这类范围中大值出现过多。

这属于基础量分布改造，和增长率连续采样可以独立实施。

## 9. 精度与可算性

完全连续随机会带来一个实际问题：增长率越不规则，反推结果越可能出现很长的小数，题目会从“速算训练”变成“计算器训练”。

建议采用以下策略：

1. 内部先使用未舍入的增长率完成数据关系计算。
2. 根据难度统一处理题干、选项和答案精度。
3. 选择题的正确答案和干扰项必须基于同一套展示精度生成。
4. 填空题继续使用容差判分。
5. 对特别长或过于接近的答案进行重新采样。

重新采样条件包括：

- 选项四舍五入后出现重复。
- 正确答案和干扰项无法区分。
- 题干数值超过当前难度允许的展示精度。
- 计算结果出现非有限值。
- 生成的题目不满足题型自身的约束。

因此，推荐的目标不是“每一位小数都无限随机”，而是：

> 生成过程连续随机，展示结果不规则但可读，题目关系正确且仍然适合练习。

## 10. 测试方案

实现后需要进行两类测试。

### 10.1 规则测试

针对每个题材和每个难度，验证：

- 所有增长率都位于题材硬边界内。
- 不会出现小于或等于 `-100%` 的增长率。
- 只允许正增长的题材不会生成负增长。
- 允许负增长的题材能够覆盖负增长样本。
- 生成的 `A`、`B`、`X` 关系始终成立。
- 选项仍然唯一且包含正确答案。
- 固定随机种子时结果可复现。

### 10.2 分布测试

使用固定种子生成至少 `10000` 题，统计：

- 小幅、中幅、大幅和超大幅区间的比例。
- 正增长、负增长和零增长的比例。
- 增长率绝对值的中位数、`P90` 和最大值。
- 各题材之间的分布差异。
- 不规则值的重复率。

重点不是要求每批数据严格等于配置比例，而是确认：

```text
小幅变化明显多于大幅变化
大幅变化不会完全消失
极端变化不会大量出现
题材之间不会出现明显违和的增长率
```

## 11. 实施步骤

建议分阶段实施：

1. 新增连续随机采样器，暂时保留 `growthRange` 作为硬边界。
2. 使用分段权重和区间内幂函数采样替换 `GrowthRatePool`。
3. 增加正负方向配置和极端尾部配置。
4. 将采样精度与展示精度分离。
5. 增加各题材和各难度的分布测试。
6. 根据统计结果调整权重，不再维护固定增长率列表。
7. 最后再为特殊低基数题材扩展到 `50%` 以上的增长率。

## 12. 风险与取舍

### 风险一：随机结果过于复杂

如果增长率精度过高，题目会出现大量难以手算的小数。

处理方式：内部连续采样，展示时按难度量化，并对不可读题目重新生成。

### 风险二：全局范围过宽

如果所有题材都允许 `-50%..50%`，GDP、人口等题目会不符合现实。

处理方式：全局算法只负责采样，题材配置负责决定硬边界。

### 风险三：尾部样本过少或过多

尾部概率过低会失去困难题价值，过高又会导致题目失真。

处理方式：先使用固定初始权重，再通过大样本统计测试校准。

### 风险四：题型之间的约束不一致

增长率本身合法，不代表比重、平均数、倍数等题型一定合法。

处理方式：增长率生成完成后，仍然必须经过各题型生成器自己的约束校验。

## 13. 最终建议

推荐采用以下原则：

```text
不用固定增长率池
不用所有题材共用一个范围
不用全区间均匀随机

改为：
题材硬边界
    + 正负方向配置
    + 分段概率
    + 区间内向小值偏置
    + 难度控制精度和尾部概率
    + 生成后关系校验
```

该方案可以实现用户提出的“不规则、连续、随机、大小概率不同”的增长率，同时保留资料分析题目必须具备的现实性和可判分性。

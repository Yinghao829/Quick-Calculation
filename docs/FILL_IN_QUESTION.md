可以。对于你的**资料分析填空题**，我建议不要追求“计算器级精度”，而是把重点放在**考察计算方法 + 控制答案精度 + 保证答案唯一**。

## 1. 核心原则

填空题和选择题最大的区别是：

> **没有选项帮考生纠错，所以答案必须设计得稳定、明确，但不需要特别高精度。**

建议统一采用：

```text
整数 → 直接取整数
百分比 → 保留1位小数
小数 → 保留1位或2位
金额/人数等 → 根据题目单位取整
```

例如：

```text
实际计算：21.8267%

答案：21.8%
```

而不是要求：

```text
21.8267%
```

---

# 2. 填空题精度等级

建议直接设计三档。

### EASY

```text
整数
整十
整百
简单百分比
```

例如：

```text
600 ÷ 1.2 = 500
```

答案：

```text
500
```

---

### NORMAL

允许一定小数：

```text
12.5%
16.7%
21.8%
35.6
```

统一：

```text
百分比：1位小数
普通数值：1~2位小数
```

---

### HARD

可以出现：

```text
12.37%
21.82%
```

但也不建议超过两位小数。

**不建议出现：**

```text
21.826734%
```

这种精度对于行测训练意义不大。

---

# 3. 不同题型的精度

建议建立一个统一的 `PrecisionPolicy`：

```kotlin
enum class Precision {
    INTEGER,
    ONE_DECIMAL,
    TWO_DECIMAL
}
```

然后：

```kotlin
data class PrecisionPolicy(
    val answerPrecision: Precision,
    val unit: String,
    val roundingMode: RoundingMode
)
```

例如：

| 题型    | 推荐精度    |
| ----- | ------- |
| 基期量   | 整数/1位小数 |
| 增长量   | 整数      |
| 增长率   | 1位小数    |
| 比重    | 1位小数    |
| 比重变化  | 1位小数    |
| 倍数    | 1位小数    |
| 平均数   | 1位小数    |
| 间隔增长率 | 1位小数    |

# 4. 最重要：不要先随机数据，再强行四舍五入

这是你生成引擎里非常重要的一点。

例如：

```text
原始答案 = 21.8267%
```

直接：

```text
21.8%
```

通常没问题。

但是如果题目涉及**多个计算步骤**：

```text
A → B → C → 答案
```

不要：

```text
A计算
↓
四舍五入
↓
B计算
↓
四舍五入
↓
C计算
```

这样误差会不断累积。

应该：

```text
原始数据
   ↓
完整计算
   ↓
得到最终答案
   ↓
最后统一四舍五入
```

即：

> **中间过程保留高精度，最终答案才进行精度控制。**

---

# 5. 填空题最适合的答案生成方式

建议：

```text
真实数据
 ↓
计算原始答案
 ↓
答案合法性检查
 ↓
最终统一格式化
 ↓
生成填空答案
```

例如：

```text
现期 = 680
增长率 = 20%

基期 = 680 ÷ 1.2
     = 566.666666...
```

最终：

```text
566.7
```

而不是：

```text
566
```

---

# 6. 可以进一步控制“答案是否好算”

这是我比较建议你加入的。

因为你做的是**行测训练 App**，并不是数学计算器。

例如随机生成：

```text
现期 = 713
增长率 = 17%
```

那么：

```text
713 ÷ 1.17 = 609.4017...
```

虽然数学上完全正确，但作为基础填空题体验不好。

可以增加：

```kotlin
AnswerQualityValidator
```

检查：

```text
□ 是否需要过多位小数
□ 是否出现特别复杂的除法
□ 是否容易心算/估算
□ 是否符合当前难度
□ 是否存在更好的数据组合
```

如果不合格：

```text
重新生成数据
```

# 8. 特别适合资料分析的设计

实际上，你可以反过来生成数据。

例如你希望答案是：

```text
25%
```

那么不要随机生成数据。

直接：

```text
基期 = 400
增长率 = 25%

现期 = 500
```

这样：

```text
增长量 = 100
增长率 = 25%
```

所有数据都很干净。

也就是说：

> **对于填空题，可以采用“答案驱动的数据生成”。**

流程：

```text
确定题型
 ↓
确定期望答案类型
 ↓
生成容易计算的参数
 ↓
反推原始数据
 ↓
生成材料
```

## 11. 我最推荐你采用的规则

你的 App 第一版直接定成：

```text
EASY
→ 整数、简单百分比
→ 最多1位小数

NORMAL
→ 整数、1位小数
→ 百分比保留1位

HARD
→ 允许2位小数
→ 百分比最多2位
```

并且严格遵守：

> **所有中间计算使用原始高精度数据，只有最终答案进行四舍五入。**

同时增加一个**答案质量检查器**，避免生成“数学上正确，但作为行测题很别扭”的数据。

这样你的**填空题生成器**和前面设计的**选择题生成器**就能共用同一套“现实数据生成 + 约束校验 + 难度控制”底层，只是在最后一步分别进入：

```text
选择题 → 正确答案 + 错误模型 → 选项生成

填空题 → 原始答案 → 精度控制 → 最终答案
```

这会是比较干净的架构。

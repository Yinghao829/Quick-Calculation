# 行测·资料分析刷题 App —— 项目规划

> 应用名：Quick Calculation（速算练习）
> 包名：`com.example.quickcalculation`
> 技术栈：Kotlin + Jetpack Compose（已配置，可编译）

---

## 1. 项目概述

为备考公务员行测「资料分析」模块的考生，提供一个**自动出题、自动判分、附带答案解析**的刷题工具。

资料分析的核心是四组基本量之间的换算：**现期量、基期量、增长量、增长率**，以及由此派生的**比重、平均数、倍数、特殊增长率**等题型。本 App 自动生成这些类型的数据题，用户作答后即时判断对错并给出正确答案与计算过程。

### 核心价值

1. **海量随机出题**——参数随机生成，练习量不受题库限制。
2. **即时反馈**——判分 + 正确答案 + 计算过程，形成完整学习闭环。
3. **贴近真题**——数值范围、选项干扰策略参照真实行测命题风格。

## 3. 题型与公式设计（核心）

> 记法：`A`=现期量，`B`=基期量，`X`=增长量，`r`=增长率（小数形式，如 12.5% = 0.125）。

### 3.1 基期与现期

| 子类型 | 已知 | 求 | 公式 |
|--------|------|-----|------|
| 求基期量 | 现期 A、增长率 r | B | `B = A ÷ (1 + r)` |
| 求现期量 | 基期 B、增长率 r | A | `A = B × (1 + r)` |

### 3.2 增长量

| 子类型 | 已知 | 求 | 公式 |
|--------|------|-----|------|
| 求增长量(现期+基期) | A、B | X | `X = A − B` |
| 求增长量(现期+增长率) | A、r | X | `X = A − A÷(1+r)`，即 `X = A·r ÷ (1+r)` |

### 3.3 一般增长率

| 子类型 | 已知 | 求 | 公式 |
|--------|------|-----|------|
| 求增长率(现期+基期) | A、B | r | `r = (A − B) ÷ B` |
| 求增长率(增长量+基期) | X、B | r | `r = X ÷ B` |

### 3.4 比重

> 记法：`a`=部分增长率，`b`=整体增长率，`P`=部分现期，`Q`=整体现期。

| 子类型 | 公式 |
|--------|------|
| 现期比重 | `现期比重 = P ÷ Q` |
| 基期比重 | `基期比重 = (P÷Q) × (1+b) ÷ (1+a)` |
| 两期比重差 | `两期比重差 = (P÷Q) × (a−b) ÷ (1+a)` |

### 3.5 平均数

| 子类型 | 公式 |
|--------|------|
| 现期平均数 | `平均数 = 总量 ÷ 个数` |
| 基期平均数 | `基期平均数 = (总量÷(1+a)) ÷ (个数÷(1+b))`，`a`=总量增速，`b`=个数增速 |

### 3.6 倍数

| 子类型 | 公式 |
|--------|------|
| 现期倍数 | `倍数 = A ÷ B`（A 为较大者） |
| 基期倍数 | `基期倍数 = (A÷(1+a)) ÷ (B÷(1+b))` |

### 3.7 特殊增长率

| 子类型 | 公式 |
|--------|------|
| 间隔增长率 | `r = r₁ + r₂ + r₁·r₂`（两年复合增速） |
| 混合增长率 | 整体增速介于两部分增速之间，偏向基期量大的一方（定性判断为主） |

## 4. 出题算法设计

### 4.1 生成器总体架构

出题器**不是简单随机数**，而是三层结构：

```
┌─────────────────────────────────────────────┐
│  难度控制层（Difficulty）                    │  ← 决定"多难"
│  简单 / 中等 / 困难，全局调参                │
├─────────────────────────────────────────────┤
│  规则驱动层（Rule-driven）                   │  ← 保证"像真的"
│  题材库 + 数据一致性规则 + 时间情境规则       │
├─────────────────────────────────────────────┤
│  约束随机层（Constrained Random）             │  ← 保证"可算"
│  在规则划定的取值域内随机，附加整除/整洁约束   │
└─────────────────────────────────────────────┘
```

**核心目标**：每一道题的数据都像现实中的统计数据，同时保证符合行测资料分析的计算特点（数值量级真实、增长率区间合理、答案干净可手算、干扰项"错得像"）。

三层职责分离，各自独立演进：换题材、调难度、加约束互不干扰。

---

### 4.2 规则驱动层（Rule-driven）——让数据"像真的"

#### 4.2.1 题材库（Topic / Dataset）

出题先从**题材库**选取一个真实统计指标作为情境，每个题材固化了量级、单位、增速合理区间：

| 题材 | 单位 | 量级 | 增速合理区间 | 备注 |
|------|------|------|-------------|------|
| 国内生产总值（GDP） | 亿元 | 万级（如 120000） | 2% ~ 8% | 常见情境 |
| 社会消费品零售总额 | 亿元 | 千级~万级 | 3% ~ 10% | 常见情境 |
| 进出口总额 | 亿美元 | 千级 | −10% ~ 15% | 允许负增长 |
| 规模以上工业增加值 | %（增速） | 个位数 | 2% ~ 8% | 常用于增速题 |
| 固定资产投资 | 亿元 | 千级 | −5% ~ 10% | 允许负增长 |
| 居民人均可支配收入 | 元 | 万级（如 35000） | 3% ~ 8% | 平均数题常用 |
| 常住人口 | 万人 | 百级~千级 | 0% ~ 2% | 增速极低 |
| 居民消费价格（CPI） | %（同比） | 个位数 | 0% ~ 3% | 增速极低 |

> 题材库以数据驱动，后续可持续扩充。每个题材的「增速合理区间」保证增长率的取值不会违背现实常识（如 CPI 不可能暴涨 30%）。

#### 4.2.2 数据一致性规则（硬约束，违反即重新生成）

| 规则 | 说明 |
|------|------|
| R1 基期为正 | 基期量 B > 0，且现期量 A > 0 |
| R2 比重在 (0,1) | 部分量 < 整体量，多部分时部分之和 = 整体 |
| R3 现期关系成立 | A = B × (1+r)，r 为负时 A 仍 > 0 |
| R4 增长量符号一致 | 增长量 X 的正负号与 r 一致（r>0 则 X>0） |
| R5 增速符合题材 | r 必须落在题材的「增速合理区间」内 |

#### 4.2.3 时间情境规则

| 情境 | 模板 | 用途 |
|------|------|------|
| 单年同比 | "2023 年 XX 为 …，同比增长 …" | 基期/现期/增长量 |
| 两年间隔 | "2022 年增长 a%，2023 年增长 b%" | 间隔增长率 |
| 两年对比 | "2023 年 XX 为 A，2022 年为 B" | 一般增长率 |
| 部分与整体 | "其中 … 占 … 的比重" | 比重题 |

---

### 4.3 约束随机层（Constrained Random）——让数据"可算"

在规则划定的取值域内随机，同时附加**整洁性约束**，确保答案干净、适合手算：

| 约束 | 说明 |
|------|------|
| C1 增长率取值域 | r 优先取**有限小数**对应的常见百分数（如 5%、10%、12.5%、20%、25%），避免除不尽 |
| C2 整洁性约束 | 生成的 A、B、X 四舍五入后 ≤ 3 位有效数字，避免冗长小数 |
| C3 反推优先 | 先定"好算"的参数（如 r 取 1/8、1/20 等），再反推其余量，而非先随机再硬算 |
| C4 答案可判性 | 正确答案与干扰项在同一量级，差值清晰可辨 |

**关键原则**：先定"好算"的参数，再反推其余量，避免出现无限小数导致答案不干净。

---

### 4.4 难度控制层（Difficulty Control）——决定"多难"

难度分三档，作为全局参数注入到规则层与随机层，逐档收紧：

| 维度 | 简单 | 中等 | 困难 |
|------|------|------|------|
| 增长率 | 整数（5%、10%） | 一位小数或常见分数（12.5%、16.7%） | 两位小数、接近临界值 |
| 数值精度 | 整数 / 整百整千 | 保留 1 位小数 | 保留 2 位小数 |
| 计算步数 | 一步 | 两步（先求中间量） | 多步 / 需截位估算 |
| 干扰项差距 | 明显（与正确项差 ≥5%） | 适中（差 1%~3%） | 极小（差 ≤0.5%，或符号陷阱） |
| 情境复杂度 | 单一主体 | 两主体对比 | 部分-整体嵌套 |

难度等级作为 `QuestionGenerator` 的入参，各题型生成器据此调参。

---

### 4.5 题目结构

```kotlin
data class Question(
    val type: QuestionType,       // 大类
    val subType: String,          // 子类型描述，如"求基期量"
    val topic: String,            // 题材，如"国内生产总值"
    val stem: String,             // 题干文本（含情境描述）
    val correctAnswer: Double,    // 正确答案
    val options: List<Double>,    // 4 个选项（选择模式，升序/乱序）
    val unit: String,             // 单位：亿元 / 万人 / % 等
    val explanation: String,      // 计算过程
    val difficulty: Difficulty,   // 难度等级
)
```

---

### 4.6 干扰项生成（选择题）

参照真题命题思路，4 个选项中 1 个正确 + 3 个干扰，干扰项来自：

1. **计算错误型**——如把 `÷(1+r)` 错成 `×(1−r)`（最典型）。
2. **符号错误型**——增长率正负号搞反。
3. **概念混淆型**——把增长量当基期、把现期当基期等。
4. **精度差异型**——四舍五入到不同位数。

**约束**：4 个选项互不重复、量级一致、唯一正确；干扰项差距由难度等级控制（见 4.4）。

---

### 4.7 填空题容差

填空题不要求精确到小数点后多位，判分采用**相对容差**：

```
判对条件：|用户答案 − 正确答案| / |正确答案| ≤ 0.5%
```

同时允许用户省略单位，答案保留若干位小数即可。容差阈值可随难度收紧（困难档可降到 0.2%）。

## 5. 判分逻辑设计

```
用户提交答案
  ├─ 选择题模式：比较所选选项 index 是否为正确选项 index
  └─ 填空题模式：解析输入数值 → 按相对容差 0.5% 判对错

判分结果 → 更新统计（答题数、正确数、正确率）→ 展示解析
```

## 6. 技术架构设计

### 6.1 分层结构（MVVM）

```
ui/            # Compose 界面层
  ├─ MainActivity.kt
  ├─ QuestionScreen.kt      # 主刷题界面
  ├─ TypeSelectScreen.kt    # 题型选择界面
  └─ theme/                 # 主题

domain/        # 业务层（纯 Kotlin，可单测）
  ├─ model/
  │    ├─ Question.kt        # 题目模型
  │    ├─ QuestionType.kt    # 题型枚举
  │    ├─ Difficulty.kt      # 难度等级枚举
  │    └─ Topic.kt           # 题材定义（题材库）
  ├─ generator/
  │    ├─ QuestionGenerator.kt    # 出题器入口（分发到各题型）
  │    ├─ TopicRepository.kt      # 题材库（规则驱动层）
  │    ├─ BasePeriodGenerator.kt  # 基期现期
  │    ├─ GrowthAmountGenerator.kt# 增长量
  │    ├─ GrowthRateGenerator.kt  # 一般增长率
  │    ├─ RatioGenerator.kt       # 比重
  │    ├─ AverageGenerator.kt     # 平均数
  │    ├─ MultipleGenerator.kt    # 倍数
  │    └─ SpecialRateGenerator.kt # 特殊增长率
  └─ judge/
       └─ AnswerJudge.kt     # 判分器

viewmodel/
  └─ QuizViewModel.kt        # 状态管理

util/
  └─ NumberUtil.kt           # 四舍五入、格式化
```

### 6.2 关键设计决策

1. **出题逻辑放 `domain` 纯 Kotlin 层**——不依赖 Android，可用 JVM 单元测试覆盖，保证算法正确性。
2. **生成器按题型拆成独立类**——每个大类一个文件，通过 `QuestionGenerator` 统一分发，便于扩展新题型。
3. **答案在生成时就计算好**——判分只做比较，不重复计算。
4. **用 `Random(seed)` 可复现**——便于测试时复现同一道题。

## 10. 风险与注意事项

1. **数值精度**——增长率涉及浮点运算，答案需四舍五入到合理位数，判分用相对容差规避浮点误差。
2. **干扰项质量**——选择题干扰项需"错得像"，避免过于明显；后续可人工校验常用干扰模式。
3. **手算友好度**——增长率优先取整/5 的倍数，降低口算负担，符合刷题场景。
4. **题型扩展**——架构上生成器按题型独立，新增题型只需加一个生成器类并注册到分发器。
